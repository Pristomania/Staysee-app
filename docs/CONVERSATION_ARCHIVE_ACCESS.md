# StaySee AI — замки и удаление бесед,20.11.2026

## Статус

Локальная реализация подготовлена в `codex/robokassa-test-payments-20261119`. Не закоммичена, не отправлена в GitHub, не применена к production. Боевые аккаунты, сообщения, модели, платежи и настройки не использовались. Старую работу и отдельную рабочую копию Claude не меняла.

Это результат локального этапа, **не разрешение включать продажи**. Полная серверная проверка Deno остаётся красной на55 исходных диагностик. Сборка `dist` сделана с фиктивным публичным ключом для проверки: **её нельзя копировать на сайт**.

## Что реализовано

- Серверный ID доступной беседы. Пока оплаченный тариф действует, актуальная активность/ручное перемещение выбирают верхнюю. После срока ID фиксирован, даже если quota ещё не вызывали. Ноль сообщений не закрывает действующий тариф.
- Free читает только этот ID. Архив сохраняется и виден в безопасном списке: название, даты, замок. Пересказ, metadata, сообщения, превью и embedding-данные закрытой беседы не выдаются через обычный пользовательский SQL/RPC. Альтернативные UI-экраны и сервисные read endpoints получили проверки доступа.
- Закрытую беседу можно удалить отдельно без оплаты. Удаление доступной не открывает следующую архивную, но позволяет новую пустую. Удаление всех работает через атомарный self RPC с ожидаемым UID из подтверждения.
- Переименование не меняет порядок. Оплаченный пользователь может переместить беседу наверх; есть пункт меню, desktop drag и логика удержания/переноса для touch. Реальный телефонный жест пока отдельно не проверен.
- Сохранённые заметки получают неизменяемое происхождение: существующий ON DELETE SET NULL не превращает заметки закрытой беседы в общие. Сами заметки не удаляются этим механизмом. Историческую уже утраченную привязку не угадываем.
- Ручные/unlimited и явные ручные многокомнатные назначения сохранены. Дополнительные архивные замки при premium→basic не вводились.
- Подтверждённая память/legacy opt-in не переписаны. Сохранены чтение глобальных поправок у платного пользователя и существующее редактирование legacy summary через узкий RPC; поменялись только границы доступа/транспорт.
- Клиент использует неповторяемое поколение проверки прав. Старые проверки, история, preview, экспорт и ответы не восстанавливают данные после смены аккаунта/потери прав. Неподтверждённая запись пары сообщений не показывается как успешно сохранённая: текст возвращается в поле ввода.

## Независимое ревью и один проход исправлений

## Принятые инженерные решения и цена ошибки

1. БД-политики + safe RPC, не только React. Если выложить только половину связки, старый frontend потеряет raw deletion/update; миграция и клиент должны приниматься вместе.
2. Tombstone без FK и новая пустая вместо открытия архива. Ошибка ротации раскрыла бы старую переписку, поэтому удаления/создание протестированы отдельно.
3. Поддержка legacy manual/unlimited/override без открытия платных features raw-free. Неверное применение исключения расширило бы коммерческий доступ; оно остаётся серверной ручной настройкой, клиент её не назначает.
4. Сохранение note provenance без удаления заметок. Цена консервативного решения — часть осиротевших заметок не видна на free; они сохранены и доступны при paid. Старую неизвестную provenance не восстанавливаем догадкой.
5. Статeless и read-only images-capability путь оставлены совместимыми: без ID они не читают архив. Неверное расширение статeless в будущем потребует отдельного guard.
6. При navigation разрешённой беседы lease живёт; при реальном отзыве полномочий отменяется. Уже авторизованный server provider in-flight не считается отозванным/возмещённым. Неподтверждённая запись не маскируется UI-успехом.
7. Авторизация/expiry/quota — по одному post-lock времени, не произвольному клиентскому timestamp. Private time-taking helpers недоступны authenticated/service RPC; иначе можно было бы передать старую дату.
8. Сохранены рабочее дерево, логи и незакоммиченные изменения; никаких merge/push/deploy/очистки чужих файлов. Удалены только собственные временные baseline-копии кода. Номера095–098/общие frontend-файлы нужно сверить с работой Claude перед объединением.

## Отложенные Minor из ревью

- При исходном сбое именно billing snapshot общий loading может остаться без встроенной кнопки retry; retry доступа работает, но это не то же самое. У Privacy delete-all ошибки также нет отдельного in-place retry. Нужен небольшой отдельный UX-проход; перезагрузка — текущий обход.
- Raw-free служебные unlimited/ручные многокомнатные пользователи не видят reorder в UI, хотя сервер его допускает. Текст о лимите ещё советует удалить беседу без уточнения, что на free место освобождает именно доступная, а не архивная.
- Замечание StrictMode об aborted memoized controller устранено при исправлении lease: renew восстанавливает controller на replay, getter выдаёт актуальный signal. Отдельного StrictMode-only автомата нет; текущий fixture работает в StrictMode.
