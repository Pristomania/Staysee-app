## Решения и ограничения

1. Выделен узкий совместимый патч создания перед полными замками. Цена ошибки в трактовке его статуса — возможность принять неполную защиту за готовую; поэтому чтение/превью/экспорт явно остаются незавершёнными.
2. Тест отказа внутри транзакции использует прямой INSERT, чтобы RESET ROLE не маскировал исходный P0001 после abort. Остальные успешные/отклонённые insert идут от authenticated. Это не полная приёмка PostgREST/RLS.
3. Порядок блокировки просмотрен, часы проверены внутри одной транзакции. Многосессионную конкурентность и ожидание блокировки на настоящем PostgreSQL PGlite не доказывает. Случай отсутствующей usage-строки не получает row lock; конкурентная гарантия этого старого пути остаётся до live отдельной задачей.
4. Независимый reviewer не проверял остальную платёжную ветку, production, архивные замки, удаление/сортировку и premium→basic. Это остаётся отдельным объёмом; не считать оценку одобрением всех платежей.

Отложенное Minor: независимый override при обычной истёкшей покупке ещё не выделен отдельным SQL-тестом; текущий тест проверяет override вместе с unlimited. SQL применяет override независимо, но перед live добавить отдельную проверку.
