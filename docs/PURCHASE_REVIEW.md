# Подтверждение условий перед тестовым заказом —20.11.2026

Пользователь сообщил: магазин ещё на проверке, чеки выбраны через Робочеки. Поэтому реальные оплаты/чеки не включались; продолжена подготовка безопасного тестового пути.

## Что сделано

В существующей технической панели выбор продукта теперь сначала открывает карточку условий. Только «Создать тестовый заказ» вызывает прежний контроллер. «Отмена» возвращает выбор и фокус на выбранную кнопку, не создаёт заказ/попытку и не сохраняет их. Отдельный переход в тестовую кассу появляется после создания заказа. Все предупреждения о тестовом режиме остаются; после test_paid повторный выбор снова проходит карточку условий.

Данные берутся из единого PLANS/PACK. «Премиум»:4900₽,1000 включённых сообщений, новый30дневный срок с подтверждения; остаток «Базового» не переносится, докупленные сообщения сохраняются с прежним сроком. Покупка тарифа завершает пробный остаток. Пакет:100сообщений за590₽ на12месяцев, расход после включённого лимита, не меняет тариф/срок и не открывает дополнительные функции. Любая реальная покупка прекращает будущие бесплатные50. Карточка явно описывает только разовый тестовый сценарий — автоподписка не считается готовой.

Это **объяснение продукта в тесте**, не авторитетный серверный quote и не решение о доступности настоящей покупки. Для live checkout нужна отдельная сверка сохранённых сервером цены/чека/eligibility. Фискальные признаки из технического теста не утверждены и в production не переносились.

Подтверждение привязано к owner/api/storage/model. Если что-то меняется или фаза уже не допускает выбора, старое подтверждение скрывается. Защита от повторного создания остаётся у существующего PaymentTestController. Backend auth/allowlist, подписи, счётчики и SQL не менялись. Боевые кнопки PAYMENT_AVAILABLE=false и «Оплата скоро» сохранены.

Перед дальнейшим использованием статуса закрыты оба ранее оставленных UI замечания101: UUID приводятся к каноническому регистру; декодер и форматтер используют общий helper с микросекундами, так что активный остаток1микросекунда не показывает «период завершён». Оба дефекта воспроизведены тестами до правок,41/41 статус+outcome прошли.

## Независимое ревью

Один свежий read-only reviewer: нет Critical/Important, блокирующие исправления не нужны. Два Minor оставлены явно: после отмены повторного просмотра test_paid раскрывающийся список закрывается и фокус может попасть на скрытую кнопку (нужно фокусировать summary или сохранять открытое состояние); число50 в тексте возобновления пока литерал, а не PLANS.free.messages. Обычная отмена из исходного выбора проверена и возвращает видимый фокус; крайний случай повторного просмотра не считается закрытым.

Решение этапа: встроенная карточка только для технического теста вместо включения live checkout, поскольку магазин ещё проверяется. Цена решения — настоящая покупка/автоподписка и фискальная приёмка ещё не доступны. Внешняя Робокасса/Робочеки, боевые чеки, entitlement-приёмка и предыдущие backend/архив/память не оценивались этим ревью; локальный GREEN не заменяет их проверку. Ветка и доказательства сохранены без интеграции/публикации.

Следующие условия запуска остаются: активация магазина, согласованные фискальные настройки Робочеков/возвратов, live создание checkout по серверному снимку, подключение страницы результата и настоящая тестовая приёмка провайдера; отдельно автопродление и lifecycle-уведомления. Этот этап их не имитирует.
