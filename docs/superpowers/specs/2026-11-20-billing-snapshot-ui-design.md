# StaySee AI: серверный снимок тарифа и счётчик

Продолжение согласованного серверного095 этапа и просьбы пользователя продолжать. Не активировать продажи/production, не менять память/модели/копию Claude.26 старых Deno-ошибок диагностированы отдельно, не исправляются этим этапом.

## Выбор и цель
Для кабинета нужен согласованный собственный снимок: effective tier, текущая квота/пакеты, срок, время сервера и признак возобновления. Выбран один self-scoped PostgreSQL RPC вместо отдельных raw чтений (те могут разойтись во времени/пользователе) или вычисления срока по часам телефона. Новый RPC096 и новая UI-сборка требуют совместной выкладки после оставшихся этапов, не делать fallback в старые небезопасные обещания.

RPC get_my_billing_snapshot() без user_id аргумента, SECURITY DEFINER search_path='', auth.uid() обязателен; гостям исполнение закрыто. Берёт usage FOR UPDATE для согласования с grant/quota, проверяет profile/suspension/deletion, затем clock_timestamp. Только собственные безопасные поля usage и packs, version1,userId,serverNow. Не отдаёт деньги/лимиты расходов/payment refs/других людей. Чтение **не меняет** квоту, историю и срок; истёкший purchased tier отражается как free/used50 в JSON, без UPDATE. Manual/unlimited сохраняются. RPC даёт только снимок — не заменяет будущие серверные замки чтения бесед.

## Клиент и время
Отдельный pure контроллер принимает fetchSnapshot(userId,signal), монотонное время performance.now и таймеры. Снимок проверяет форму, версию, владельца, корректные zoned timestamps, допустимые числа/tier/source. Нет auth-секретов в состоянии/URL/логах. Часам устройства не доверяет. Консервативная привязка к началу запроса (полный RTT вычитается из доступного срока) и неубывающий серверный floor не позволяют позднему/повторно отданному старому снимку продлить доступ. Ожидание15сек, отмена на unmount/смене пользователя, request-generation защита от out-of-order.

Сетевая ошибка сохраняет ранее известный снимок, но его deadline продолжает идти. На точной границе срока права/квота меняются локально по серверному якорю даже при недоступном RPC; пакеты также истекают. После этого запрашивается свежий снимок. Успешный ответ null (аккаунт недоступен/usage отсутствует) закрывает прежние права; непроверенный/неправильный ответ не даёт новых прав. При первой неудаче данных нет и платные функции не открыты. Смена аккаунта ни на один render не показывает старый tier/counter. На visibility/online и после отправки используется refresh. Таймеры ограничены ближайшей meaningful границей, не бесконечный polling. Технический manual доступ сохраняется, но не считается оплатой.

Builder check уточнил сон устройства: при foreground/pageshow/online требуется свежее подтверждение, до него прежние платные функции временно закрыты. При расхождении wall-clock/monotonic при heartbeat (сон или ручная смена часов) также только инвалидировать и перечитать, никогда не продлевать по wall-clock. Низкочастотный heartbeat проверяет часы локально, не вызывает периодических сетевых запросов. Неудача такой обязательной проверки сохраняет данные внутри контроллера, но не возвращает права; показывать «Не удалось проверить тариф. Повторно оплачивать не нужно» и кнопку проверки, а не платежную продажу. Сдвиг часов может только потребовать проверку, не выдать доступ.

## Квоты и тексты
- Купленный тариф не обновляет сообщения по календарю: remaining=max(0,limit-used), paidUntil отдельно; при истечении trial0, купленные остатки сохраняются.
- Ранее плативший free не получает новый free50/дату возобновления. Пакет сохраняет первоначальный trial, пока тот не использован. Never-paid free и legacy manual месяцы сохраняют прежнее правило.
- Нулевой баланс не выключает платные функции до срока. Строка срока «Оплачен до…» не обещает новых сообщений в эту дату. Карточка бесплатного тарифа для ранее платившего не обещает новые50.
- Серверный отказ после real purchase не обещает автообновления: добавить проверенный boolean can_renew_messages в reserve и RateLimitResult; старые ответы без поля сохраняют прежнюю совместимость. При false — спокойное «Сообщения закончились. Беседа сохранена». Минимальная правка только billing-ветки отказа staysee-chat, без промптов/моделей/памяти.
- Существующий PlanProvider остаётся точкой подключения всех экранов, получает validated snapshot/controller. Старые источники не удалять вне затронутых вызовов. has неизвестного тарифа=false, не открывать всё до чтения. Никаких настоящих grants/внешних оплат при браузерной приёмке.

## Приёмка и границы
Pure tests: несоответствие владельца/формы/дат; expiry и0quota; пакеты/first purchase/no renewal; часы устройства; out-of-order/disposal/timeouts; failed refresh послеdeadline; replay старого snapshot; next deadline. SQL PGlite на реальных085–096: self-only/guest/ACL, no financial fields, read-only snapshot0quota/expiry/packs/manual, can_renew_messages в реальном reserve. Browser на actual provider/controller с изолированным RPC fixture: нулевой paid баланс сохраняет функции, term deadline закрывает их, no fake renewal, account switch и телефонная ширина. Full offline/typecheck/build и одно свежее review.

Не заявлять, что готовы archive RLS/сортировка/чистка ранее загруженной переписки, все серверные feature-boundary races, реальный provider callback или полная Supabase/concurrency. Это следующие этапы до live. Код/миграции не применять и не коммитить без отдельного объединения с Claude.

Уточнения по review: отзыв/null не стирает историю принятого серверного времени; новые данные старше последнего подтверждения запрещены. Микросекундный порядок сохраняется отдельно от миллисекундного UI-таймера. На получении ответа проверяется clock-discontinuity за весь запрос **до** обновления heartbeat anchors. Клиентская дата из предыдущей отправки не имеет приоритета над свежим текстом Edge. Все общие locked panels/badges различают unknown и реально закрытое; старый upsell сбрасывается при смене identity/loaded/tier.
