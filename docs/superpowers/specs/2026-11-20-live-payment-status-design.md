# Проверка своего оплаченного заказа — следующий локальный этап

Пользователь просит продолжать оплату по порядку. До включения checkout нужен доверенный read-path: возврат из кассы не доказывает оплату. Сохраняем ранее выбранное выполнение без повторных согласований локальных шагов. Не внедряем новый платёжный провайдер/реальную оплату, не принимаем фискальных решений за пользователя.

Подход: authenticated self-only RPC get_my_live_payment_status(p_order_id uuid) в101 вместо нового service-role HTTP endpoint. Это использует существующую авторизацию, не требует ещё одного секрета и не открывает таблицу ledger. Browser получает только собственный заказ по UUID и свежий get_my_billing_snapshot, не передаёт userId для авторизации. Гость/service_role без self identity не вызывают RPC. Чужой/несуществующий заказ и недоступный аккаунт возвращают одинаковый NULL. Lock usage первым, затем читать заказ/snapshot: тот же порядок, что confirmation. Никакого grant/reserve/expiry-записывания при чтении.

DTO version1: order(id,productId,purchaseKind,amountKopecks,status,expiresAt,paidAt,appliedAt,paidUntil), billing(существующий096 DTO), currentGrant:boolean. Статусы pending/expired(проекция)/applied/paid_unfulfilled. paidUntil для исторического месячного applied=appliedAt+30days, для пакета и неприменённого заказа NULL. currentGrant истинен только для applied месячного заказа, совпавшего с нынешними purchased tier/period_started_at/paid_until и ещё действующего по serverNow, не для ручного/unlimited. Старый Basic после повышения не показывать как снова включённый Basic; пакет после расхода не обещать как новые100 доступных сейчас. paid_unfulfilled означает уже учтённые деньги без исполнения, не повторную оплату.

Клиент: строгий декодер привязывает DTO к ожидаемым orderUUID/userId, повторно использует parseBillingSnapshot, отвергает extra/неверные поля и несогласованные статусы/времена/currentGrant. Читающая функция с внедрёнными session/read, одним общим deadline10s, AbortSignal, проверкой текущей сессии до и после RPC; нет бесконечного polling, записи localStorage или прав в PlanContext. Прямой адаптер Supabase RPC отдельно; страница покупки пока не подключена. Тексты pending/expired/unfulfilled и исторического applied не обещают действующий доступ.

Проверки реальные SQL/PGlite: self/чужой/гость/service ACL, независимость статуса от gate создания, pending expiry без записи, applied/duplicate/upgrade/oldgrant/pack/удаление/блокировка, read не начисляет и не тратит. Pure browser: malformed/другойuser/order, snapshot, исторический результат, clock/session switch/abort/deadline. Полные offline/SQL/types/build и один свежий reviewer узкого этапа. Боевой provider/чеки/настоящая многосессионная БД остаются отдельными gates.

Review refinement:101 binds read and confirm timezoneUTC for a fixed30*24hour contract; no retrospective guesses for nonUTC historical periods. Own client controller aborts on every exit, including non2xx response with a hanging body. Both regressions RED→GREEN in single review fix pass.
